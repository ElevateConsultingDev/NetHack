# Engine notes (suspected bugs and missing rules; the improvement loop reads this)

Derived from the run records by `pilot.reflect`, alongside `conclusions.md`. Not in the brain's prompt.

- Elbereth engrave/rest sequence still lets an adjacent monster's attack land before or during it, killing the player regardless of HP band: seen in the large majority of this batch's deaths (15+ games: small mimic x2, werejackal packs x4, hobgoblin, giant ant, rothe, coyote, elf zombie, gecko). Written rule bans it but haiku still selects it constantly. Engine should hard-block the elbereth/rest-on-elbereth action verb whenever a hostile is adjacent.
- Critical/badly-hurt fallback still issues eat/use/quaff with no useful outcome in 8+ games this batch (wererat, giant bat, rothe, elf zombie, giant ant x2, bat, small mimic) despite explicit written ban; the eaten item is often itself bad (rotten food, rotten egg) causing extra vulnerable turns. Recommend an engine-side hard override: force fight or flee when HP is critical/badly hurt and a monster is adjacent, regardless of brain's chosen verb.
- "Brain loop" / repeated contradictory verb stalls for the same adjacent monster: still present this batch, mostly cycling elbereth then eat/use before death. Needs a forced-decision cap after N repeats.
- step_away failure fallback mostly falls to fight this batch (5+ games), a real improvement; 1 game this batch (B19490525) still fell to explore instead, which fed the no-way-on stall. Keep watching.
- rest (including rest-on-Elbereth) still executes while a hostile is adjacent and does not interrupt on incoming hits; at least 3 deaths this batch trace to this (rothe, hobgoblin, jackal games).
- No-way-on stalls persist after search_walls/search_dead_ends exhaust, now also triggered by a peaceful blocking a loot/probe target (not just stairs): 3 of 32 games this batch (peaceful gnome loot loop, red mold+homunculus block, yellow mold+dwarf zombie block), defaulting to wait/loop instead of pushing past.
- Weak/Fainting stalls: check-in consults return None for long stretches with no food-seeking fallback; one game this batch (B19490519) prayed while fainting and was punished ("Tyr is displeased") despite apparent spacing, then had no food path.
- Prayer punishment despite turn spacing: B19490519's prayer failed ~1007 turns after the prior success, similar spacing to games where prayers succeeded; spacing alone still not a reliable predictor.
- go_down still fails "no known way down" when apparently near but not on the stairs tile (recurs this batch, unchanged).
- go_to pathfinding still fails against blocked/unreachable coordinates, ignores a blocking monster in the path, and once walked the player back toward a hostile shopkeeper it had just fled from (B19490511), getting it killed by a wand of striking plus melee.
- Sleep-chain deaths: once put to sleep (homunculus bite), unanswered hits occur with no consult firing until death (1 game this batch, 5+ cumulative with golden naga gas cause).
- Loot/probe/search routines still loop against a stationary blocker (peaceful gnome, molds, homunculus, dwarf zombie) for 10+ turns before falling back (3 games this batch).
- High rate of "-> None" consult responses this batch on first-sighting and check-in prompts (dozens of instances); unclear if this is an intentional "carry on" default or haiku disengaging; worth checking if it correlates with missed early-flee opportunities before monsters closed to melee range.
- History of tried-and-dropped brain-side tweaks (loop iterations 11-27, kept so they aren't retried blind): Hungry-with-no-food go_down-before-clearing; wider rest HP band; multi-round wall search with quality fallback; keep-fighting-instead-of-Elbereth when badly hurt; Excalibur fountain-dipping; eating fresh floating eyes for telepathy; stepping into a corridor/doorway with 2+ hostiles adjacent; sticky explore target with visited-square path cost; remembering every seen-floor square for pathing; sticky explore target plus loot-only-near-hostiles. None produced a net gain; revisit only after the "no way on" or "rest doesn't interrupt" problems get a real fix.
